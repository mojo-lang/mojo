# Entity 数据库操作代码

在项目根目录执行 `mojo build -t api,service .`，同时生成 Go API 类型和
基于 NCraft / Go kit 的后端服务。数据库操作代码位于
`service-go/pkg/model`，不会写入共享的 Go API 类库。已有 Go API 时，
可用 `mojo build -t service .` 单独更新后端。仅包含 entity、没有 Interface
的包也可以生成数据库模型。

## Entity 与主键

以下三种定义都会生成模型：

```mojo
type User {
    id: String @1
    name: String @2
}

type Product {
    code: String @1 @key
    name: String @2
}

@entity
type Note {
    content: String @1
}
```

- `id` 字段会被自动识别为主键；没有 `id` 时识别 `@key`、`@db.key`
  或 `@db.primary_key` 字段。
- 显式 `@entity` 没有主键时，编译器补充 `String` 类型的 `id`，不修改
  Mojo 源文件。Protobuf 编号从 `536870911` 向下选择未占用的编号，避免
  普通字段的增加改变隐式主键编号。
- 模型支持单一 String 或整型主键。模型初始化会检查实际 GORM 主键及列名；
  不支持的主键类型会在生成时明确报错。
- 自动补充字段不等于自动分配 ID 值；调用方需为 String 主键赋值。

## 在后端中使用

模型接收服务管理的 `*db.DB`，复用已有连接和配置：

```go
import (
    "context"

    api "example.com/acme/project/go/pkg/example"
    "example.com/acme/project/service-go/pkg/model"
    "github.com/mojo-lang/mojo/go/pkg/mojo/db"
)

func createUser(ctx context.Context, database *db.DB) error {
    users, err := model.NewUser(database)
    if err != nil {
        return err
    }
    _, err = users.Create(ctx, &api.User{Id: "user-1", Name: "Alice"})
    return err
}
```

`db.New(config)` 可以创建连接，也可以传入服务已有的数据库实例。连接的
生命周期由服务管理。`DisableAutoMigrate` 为 true 时，模型构造函数不会
建表或修改表；否则调用 GORM AutoMigrate，失败时返回错误。

每个模型提供 `Create`、`Get`、`Update`、`UpdateBy`、`UpdateAll`、`UpdateAllBy`、`Delete`、`List`、`BatchCreate`、
`BatchGet`、`BatchUpdate`、`BatchUpdateAll`和 `BatchDelete`。所有操作使用传入的 context。
`Get` 和批量按键操作的参数类型与实体主键一致；`List` 接收
`db/query.Query`，使用查询条件、排序及分页。

`Update` 更新全部非零非主键字段，不插入不存在的记录。
`UpdateBy` 更新全部非零非指定字段，不插入不存在的记录（注意，指定字段如果未非主键，则有可能会更新多条数据）。
`UpdateAll` 更新全部非主键字段，包括零值，不插入不存在的记录。
`UpdateAllBy` 更新全部非指定字段，包括零值，不插入不存在的记录（注意，指定字段如果未非主键，则有可能会更新多条数据）。
`BatchUpdate`、`BatchUpdateAll` 使用事务，任一更新失败都会回滚，返回的受影响行数为零。

空的批量调用不查询或修改数据库。

模型文件带 `Code generated by mojo. DO NOT EDIT.` 标记，重新生成会更新
这些文件。手写扩展应放在没有该标记的独立文件中。
